## Compatibility work before using scan results

Compare against DefaultGameRepository using the same isolated fixtures, including malformed and typed manifests, unconventional names, inherited manifests, invalid ids, classic instances and unreadable files. This prototype currently verifies only JSON object syntax, omits the Classic special case, reports manifest id separately rather than normalizing it, imposes a size limit, and emits UTF-8 paths with lossy conversion. Never treat its output as a repository snapshot until parity is established. Scan is read-only, but other users/processes can concurrently change the directory. The download operation writes to an explicitly selected destination and is tested only with isolated local fixtures.

## Proposed order

1. Freeze supported behavior in differential tests and take a baseline on synthetic fixtures. Characterize startup, refresh, file validation, exports and memory, including warm/cold cache where safely measurable.
2. Specify a stable versioned protocol, process lifecycle, limits, timeouts, cancellation, progress and Java adapter; test failures and ownership. Integrate behind an explicit experimental selection only after behavior is verified.
3. Incrementally introduce read-only inventory; only switch an operation after parity and meaningful performance measurement.
4. Migrate downloads with temporary files, atomic finalization, checksums, resumption, bounded concurrency and failure recovery.
5. Migrate game/loader installation and process launch with platform fixtures and command-line comparison.
6. Migrate accounts and modpacks; audit credentials, license obligations, platform behavior and data migration before production use.

Each writer has exactly one owner. Prototype tests use temporary directories, never the user's game installation. Do not present any stage as finished until its acceptance tests pass on the supported systems.
